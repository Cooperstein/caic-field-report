Trip report → CAIC Data API v2

Every question on the CAIC trip report, the API field it lands in, and the conversion in between. Written for the Avalanche Canada developers wiring the form to CAIC. Copy the reference code at the bottom rather than re-deriving the tables. It was checked against the published spec.

Spec: CAIC Data API v2, version 2.55. Value lists confirmed against live production data on 26 September 2026.

Call order

None of these endpoints need an auth token. Everything after step 1 hangs off the report's id, so the report has to exist first.

  1. POST /api/v2/observation_reportsContact, privacy, pin, date, the avalanche answer and the trip summary. Returns the report with its id.
  2. POST /api/v2/observation_reports/{id}/avalanche_observationsOnce per avalanche the reporter filled in. Zero calls if they did not.
  3. POST /api/v2/observation_reports/{id}/snowpack_observationsOnce, only if Cracking or Collapsing was answered.
  4. For each photo or video: register → PUT to S3 → attachSee Photos and video. Caption and order go in the attach call.
ServerBase URL
Developmenthttps://lb-octonaut.avalanche.dev/api/v2
Productionhttps://api.avalanche.state.co.us/api/v2

Build and test against development. Every test post to production is a real public report that a forecaster has to find and delete.

2. Avalanche observations

Skip empty entries. The form always holds one blank avalanche, and a reporter can add more and leave them blank. Only send an entry with at least one answered question. Send none at all if avType is none or unanswered, even if an entry has data left over from before the reporter changed their answer.

3. Instability (snowpack observation)

POST /api/v2/observation_reports/{id}/snowpack_observations. Send one only when Cracking or Collapsing was answered.

Collapsingtr_collapsingcollapsingCapitalise: none minor moderate rumbling unknown → None Minor Moderate Rumbling Unknown

“None” is an answer, not a blank. Send "None" when the reporter picked it. Omit the field only when they skipped the question. Forecasters filter on reports that say “no cracking.”

4. Photos and video

Files go straight from the device to CAIC's S3 bucket. The API only hands out a short-lived upload URL and then links the stored file to the report. Each file takes three calls, run after the report exists.

  1. POST /api/v2/assets/registrationsBody: byte_size, checksum, content_type, filename. Returns key, signed_id and direct_upload.url + direct_upload.headers.
  2. PUT the raw bytes to direct_upload.urlSend exactly the headers the registration returned and nothing else. PUT, not POST: a POST fails the checksum.
  3. POST /api/v2/observation_reports/{id}/attachmentsBody: key, signed_id, plus the photo's caption and its position (1, 2, 3… in the order shown on the form). Leave out the deprecated type field.
FormWhere it goes
The file (assets[i].file)Registration: byte_size = file size in bytes, filename = base name only (no folders), content_type = MIME type
Caption (assets[i].caption)Attach: caption. Trim, and omit if empty.
Order in the photo stripAttach: position, starting at 1

The checksum is the one that trips people up. It is the base64 of the raw 16-byte MD5 digest: bymH1431LAiMufALW2h2zw==, 24 characters. It is not the 32-character hex string md5sum prints, and not base64 of that hex string. S3 rejects the PUT if it is wrong.

Browsers have no built-in MD5 (Web Crypto has no MD5), so the example uses spark-md5. Native apps can use the platform's MD5 (CommonCrypto on iOS, MessageDigest on Android) and base64 the bytes.

  • Register each file immediately before its PUT. The signed URL expires after about five minutes, so registering everything up front breaks on slow connections. If a PUT fails, register again for a fresh URL.
  • Hash in slices, not with the whole file in memory. Phone video runs to hundreds of MB.
  • Upload one file at a time. Trailhead signal is poor, and parallel uploads mostly make every file slower.
  • Some browsers leave file.type empty (HEIC, some .MOV). Fall back to the file extension, and send the same value in the registration and the PUT.
  • Tags are optional and limited to what the user may set. Leave them out.

5. External links

POST /api/v2/observation_reports/{id}/external_attachments links media that lives elsewhere, typically a YouTube video, without uploading it. Body: external_url and content_type (both required), plus optional caption and position.

The trip report does not ask for links today, so nothing on the form maps here. If one is added, the server only accepts some domains and returns 400 bad url domain for the rest. Get the allowed list from CAIC rather than guessing, and show the reporter a plain message on a 400.

Reference code

buildPayloads(S) turns the form state into the request bodies above. submitTrip(S) sends them in order and uploads the files. Both are plain JavaScript with no framework. Before this page was published, they were run against six test reports: every body matched the spec's field names, types and allowed values, and the retry paths were checked against a mock server.

buildPayloads.js: form state → request bodies 
// CAIC trip report -> CAIC Data API v2 request bodies.
// Input: the form state (see "Form state" on this page). Output: one body per request.
const AV_FLAGS = {            // avType -> report booleans; exactly one is ever true
  none:      { saw_avalanche: false, triggered_avalanche: false, caught_in_avalanche: false },
  saw:       { saw_avalanche: true,  triggered_avalanche: false, caught_in_avalanche: false },
  triggered: { saw_avalanche: false, triggered_avalanche: true,  caught_in_avalanche: false },
  caught:    { saw_avalanche: false, triggered_avalanche: false, caught_in_avalanche: true  },
};
const ELEVATION = { ">TL": "&#62;TL", "TL": "TL", "<TL": "&#60;TL", "U": "U" };  // API stores the escaped text
const SIZE = { D1: "D1", D15: "D1.5", D2: "D2", D25: "D2.5", D3: "D3", D35: "D3.5",
               D4: "D4", D45: "D4.5", D5: "D5", U: "U" };
const TRIGGER_BY = { AS: "AS", AR: "AR", AI: "AI", AF: "AF", AM: "AM", AN: "AN", AK: "AK", AV: "AV",
                     other: "AO", unsure: "AU" };
const CRACKING   = { none: "None", minor: "Minor", moderate: "Moderate", shooting: "Shooting", unknown: "Unknown" };
const COLLAPSING = { none: "None", minor: "Minor", moderate: "Moderate", rumbling: "Rumbling", unknown: "Unknown" };
const AV_KEYS = ["whenOccurred", "trigger_how", "trigger_by", "aspect", "elevation", "dsize", "problem"];

const filled = v => v !== undefined && v !== null && String(v).trim() !== "";
const round6 = n => Math.round(n * 1e6) / 1e6;

// "How did this avalanche start?" picks the family; "Who or what set it off?" picks the letter after A.
// Only "from a distance" sets a secondary trigger (r). Who/what = Unsure or unanswered -> AU.
function triggers(a) {
  switch (a.trigger_how) {
    case "natural":   return { primary_trigger: "N", secondary_trigger: null };
    case "triggered": return { primary_trigger: TRIGGER_BY[a.trigger_by] || "AU", secondary_trigger: null };
    case "remote":    return { primary_trigger: TRIGGER_BY[a.trigger_by] || "AU", secondary_trigger: "r" };
    case "unknown":   return { primary_trigger: "U", secondary_trigger: null };
    default:          return {};                       // not answered: omit both
  }
}

function buildPayloads(S) {
  const lat = round6(S.lat), lng = round6(S.lng), date = S.observed_at;   // date is "YYYY-MM-DD"
  const staff = S.visibility === "staff";

  const report = {
    firstname: S.firstname.trim(), lastname: S.lastname.trim(),
    email: S.email.trim(), phone: S.phone.trim(),
    observed_at: date, date_known: "Known", time_known: "Unknown",
    latitude: lat, longitude: lng,                     // always the real pin; the server fuzzes
    is_anonymous: S.visibility !== "public",
    is_anonymous_location: S.locshare === "fuzz" || staff,
    is_locked: staff,
    ...(AV_FLAGS[S.avType] || AV_FLAGS.none),
    description: filled(S.comments) ? S.comments.trim() : null,
    hw_op_bc: "bc",
    report_source: "Mobile App",
  };

  const reported = S.avType && S.avType !== "none";   // details are ignored if the answer went back to "none"
  const avalanches = !reported ? [] : S.avalanches
    .filter(a => AV_KEYS.some(k => filled(a[k])))      // the form always holds one empty entry
    .map(a => ({
      latitude: lat, longitude: lng,
      observed_at: filled(a.occurredOn) ? a.occurredOn : date,
      date_known: a.whenOccurred === "setdate" && filled(a.occurredOn) ? "Known" : "Estimated",
      time_known: "Unknown",
      ...(filled(a.aspect)    && { aspect: a.aspect }),
      ...(filled(a.elevation) && { elevation: ELEVATION[a.elevation] }),
      ...(filled(a.dsize)     && { destructive_size: SIZE[a.dsize] }),
      ...(filled(a.problem)   && { problem_type: a.problem }),
      ...triggers(a),
      ...(filled(a.trigger_by_other) && { comments: "Triggered by: " + a.trigger_by_other.trim() }),
    }));

  const snowpack = (filled(S.tr_cracking) || filled(S.tr_collapsing)) ? {
    latitude: lat, longitude: lng, observed_at: date,
    ...(filled(S.tr_cracking)   && { cracking: CRACKING[S.tr_cracking] }),
    ...(filled(S.tr_collapsing) && { collapsing: COLLAPSING[S.tr_collapsing] }),
  } : null;

  const attachments = S.assets.map((f, i) => ({       // file is uploaded first; see "Photos and video"
    file: f.file, caption: filled(f.caption) ? f.caption.trim() : undefined, position: i + 1,
  }));

  return { report, avalanches, snowpack, attachments };
}
submitTrip.js: send the report, observations and files 
// Submit a trip report: create the report, then hang everything else off its id.
// Needs spark-md5 for the upload checksum (browsers have no built-in MD5):
//   <script src="https://cdn.jsdelivr.net/npm/spark-md5@3.0.2/spark-md5.min.js"></script>
const API = "https://lb-octonaut.avalanche.dev/api/v2";   // dev. Production: https://api.avalanche.state.co.us/api/v2

async function post(url, body, { timeout = 30000 } = {}) {
  const ctl = new AbortController(), t = setTimeout(() => ctl.abort(), timeout);
  try {
    const res = await fetch(url, { method: "POST", signal: ctl.signal,
      headers: { "Content-Type": "application/json", Accept: "application/json" },
      body: JSON.stringify(body) });
    if (!res.ok) throw Object.assign(new Error(`${res.status} on ${url}: ${await res.text()}`), { status: res.status });
    return res.json();
  } finally { clearTimeout(t); }
}

// Retry only steps that are safe to repeat: network errors, 429 and 5xx. Never a 4xx.
async function retry(fn, tries = 3) {
  for (let i = 1; ; i++) {
    try { return await fn(); }
    catch (e) {
      const transient = !e.status || e.status === 429 || e.status >= 500;
      if (!transient || i >= tries) throw e;
      await new Promise(r => setTimeout(r, 1000 * 2 ** i));
    }
  }
}

// Base64 of the raw MD5 digest -- NOT the hex string md5sum prints. Read in 2 MB slices so video fits in memory.
async function md5Base64(file) {
  const spark = new SparkMD5.ArrayBuffer(), step = 2 * 1024 * 1024;
  for (let at = 0; at < file.size; at += step)
    spark.append(await file.slice(at, at + step).arrayBuffer());
  return btoa(spark.end(true));
}

const TYPES = { jpg: "image/jpeg", jpeg: "image/jpeg", png: "image/png", heic: "image/heic",
                mp4: "video/mp4", mov: "video/quicktime", webm: "video/webm" };
const contentType = f => f.type || TYPES[f.name.split(".").pop().toLowerCase()] || "application/octet-stream";

async function uploadAsset(reportId, { file, caption, position }) {
  const checksum = await md5Base64(file);
  return retry(async () => {
    // 1. Register. The signed URL lives about 5 minutes, so register right before each PUT.
    const reg = await post(`${API}/assets/registrations`, {
      byte_size: file.size, checksum, content_type: contentType(file), filename: file.name });
    // 2. PUT (not POST) the bytes to S3 with exactly the headers the registration returned.
    const put = await fetch(reg.direct_upload.url,
      { method: "PUT", headers: reg.direct_upload.headers, body: file });
    if (!put.ok) throw Object.assign(new Error(`S3 ${put.status}: ${await put.text()}`), { status: put.status >= 500 ? put.status : undefined });
    // 3. Attach to the report, caption and order included.
    return post(`${API}/observation_reports/${reportId}/attachments`,
      { key: reg.key, signed_id: reg.signed_id, caption, position });
  });
}

async function submitTrip(S) {
  const p = buildPayloads(S);
  // The report has no idempotency key: a blind retry can create a duplicate. Post it once.
  const report = await post(`${API}/observation_reports`, p.report);
  const id = report.id, failed = [];
  const run = async (label, fn) => { try { await retry(fn); } catch (e) { failed.push({ label, error: e.message }); } };

  for (const [i, a] of p.avalanches.entries())
    await run(`avalanche ${i + 1}`, () => post(`${API}/observation_reports/${id}/avalanche_observations`, a));
  if (p.snowpack)
    await run("snowpack", () => post(`${API}/observation_reports/${id}/snowpack_observations`, p.snowpack));
  for (const att of p.attachments)                      // one at a time: phones on trailhead signal
    await run(att.file.name, () => uploadAsset(id, att));

  return { id, failed };   // keep id + failed locally and offer "Retry uploads" rather than resubmitting
}

Bug checklist

Each of these is an easy mistake that the API will either reject or, worse, accept and store wrong.

  • Post the report once. The API has no idempotency key. A blind retry after a timeout can create a duplicate public report. Keep the returned id on the device, and retry only the steps after it.
  • Never retry a 4xx. It will fail the same way. Retry network errors, 429 and 5xx with backoff.
  • Partial success is normal. A report can post while one photo fails. Tell the reporter what went through, and offer “Retry uploads,” not “Resubmit.”
  • Elevation is &#62;TL / &#60;TL, literally.
  • Sizes need the dot: D15 → D1.5.
  • Cracking and collapsing are capitalised, and "None" is a real answer.
  • Case matters everywhere: Unknown for problem type, U for aspect/elevation/size/trigger, r and U for secondary trigger.
  • Dates are local calendar dates, "YYYY-MM-DD". Converting to UTC can move a late-afternoon report to the next day.
  • Send the real pin. The server does the obfuscation. A client-side fuzz means staff lose the true location.
  • Exactly one avalanche flag is true, or none.
  • Skip blank avalanche entries, and ignore avalanche entries when the answer is back to “didn't see.”
  • Omit, don't guess. An unanswered question is left out (or null), never filled with a default like U. The server treats “unknown” and “not asked” differently.
  • Checksum is base64 of raw MD5 bytes, 24 characters ending in ==.
  • S3 upload is a PUT with the returned headers, sent within about five minutes of registering.
  • Browser builds: the API allows cross-origin calls from www.avalanche.ca. Confirm the S3 PUT works from the browser on the development server before relying on it.

Not collected yet

The API can take more than the trip report asks for. These exist in the spec, or elsewhere in this prototype, but are not on the CAIC trip form, so there is nothing to send:

  • Group and incident details (group size, number caught or buried, rescue gear, airbags)
  • Avalanche dimensions, weak layer, bed surface and crust
  • Weather observations (POST …/weather_observations)
  • Report title, activity, route and objective (report_title, report_activity, route, objective)
  • External video links

If any of these are added to the form, this page gets a new row, not a new process.
